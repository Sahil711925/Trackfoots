#TimeActorActionHash

Published roots

Every entry is hashed together with the entry before it, so one edit breaks every hash after it. Once a batch of entries is complete it is reduced to a single Merkle root and published — and once published, the server can never change that number again. An attacker with root can rewrite the file, and can even recompute every hash; he still cannot change a root that other machines already recorded.
What this does not protect against
Entries written but not yet anchored (the tail of the current batch) are protected by the hash chain only — a root-level attacker inside that window could still delete them. Closing it needs per-write receipts (implemented auditor-side, shown above) or immediate anchoring at higher cost.
